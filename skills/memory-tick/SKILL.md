# memory-tick: 기억 판단과 저장

Claude Code와 Codex에서 같은 저장 계약을 사용한다. Stop 훅은 세션별 60분에 한 번 평가를 요청하며, 타이머는 저장 성공이 아닌 평가 요청 시점 기준이다. 사용자의 명시적 저장 요청은 타이머와 무관하게 처리한다.

## 처리 순서

1. **저장 가치 판단.** 사용자 선호·명시 정정·프로젝트 제약·재사용할 외부 참조가 있는지 판단한다. 코드/git 기록으로 충분한 진행 상황, 일회성 지시, 새 근거 없는 반복 요약은 저장하지 않는다. 가치가 없으면 도구 호출이나 보고 없이 종료한다. 사례 지식 자동 추출·컴파일은 별도 후속 작업이다.
2. **저장 경로 확인.** 저장할 내용이 있으면 연결된 memory MCP를 사용한다. MCP가 없거나 오류면 저장 미완료를 짧게 알리고 종료한다. 볼트 직접 Write/셸 쓰기나 다른 저장소로 우회하지 않는다. Stop 요청은 실제 볼트 쓰기 금지 등 현재 작업의 제약을 해제하지 않는다.
3. **근거와 기존 기억 확인.** [검색 절차](../../scripts/memory-retrieval-instructions.md)에 따라 등록 프로젝트를 식별하고 관련 기억을 찾는다. 후보·레거시의 중복 확인이 필요한 저장 검토에서는 `review=true`로 조회할 수 있지만 자동 적용 권한이 생기지는 않는다. `memory_get(name)`으로 갱신 대상 원문을 확인한다. 의미·범위가 같은 기록만 갱신 대상으로 삼고, 새 정보가 없으면 종료한다.
4. **범위와 상태 결정.** 저장 전에 [기억 적용과 저장](../../scripts/memory-application-instructions.md)의 결정표를 읽고 적용한다. `scope`와 `status`는 독립이다. 등록 프로젝트 안의 직접 정정은 project/confirmed와 범위 추정 표기를 함께 쓸 수 있다. 내용 추론은 candidate, 프로젝트와 전역 근거가 모두 없으면 null/candidate로 격리한다. 프로젝트 ID를 임의 생성하거나 핵심을 자동 선정하지 않는다.
5. **검증된 저장.** `memory_save(kind, slug, description, body, tags, metadata)`에 완전한 메타데이터를 전달한다. 필드는 `memory_schema`, `scope`, `status`, `project_id`, `scope_inferred`, `scope_reason`, `status_reason`이다. 신규·레거시 전환·v1 갱신 및 오류 처리에는 [저장 계약 S1–S6](../../docs/memory-retrieval-storage-contract.md)을 따른다. 호출 결과의 격리·오류·인덱스 부분 실패를 확인하고, 저장 결과를 원문 조회로 확인한 뒤에만 완료로 판단한다. 실패를 성공으로 보고하지 않는다.

## 저장 내용과 보존

기본 볼트는 `~/99_memory/memory/`이며 연결 설정이 가리키는 볼트를 사용한다. 노트 파일명 `{type}_{slug}.md`, 기존 created와 비대상 필드, 전체 `MEMORY.md` 목록은 보존한다. 노트/인덱스의 원자 쓰기와 scrub은 MCP가 수행한다. 여러 프로세스의 동시 저장 직렬화는 보장되지 않으므로 병렬 저장을 요청하지 않는다.

- 본문에 관찰과 추론을 구분하고 출처·직접 확인한 근거를 남긴다. feedback/project는 **Why:**와 **How to apply:**로 이유와 적용 조건을 적는다. 미확인 내용을 확인된 사실로 쓰지 않는다.
- 정정은 원문을 확인한 뒤 필요한 내용·범위만 갱신한다. 현재 지시의 일회성 예외는 기존 기억의 영구 변경 근거가 아니다. 상충된 기억의 자동 삭제나 인덱스 길이에 따른 정리는 하지 않는다. 영구 변경 근거가 불명확하면 기존 기록을 보존한다.
- 후보·legacy·invalid는 자동 적용에서 제외하고 목록과 검토 조회에 보존한다. 레거시 원본 전체를 승인된 짧은 핵심과 같은 범위/상태로 승격하지 않는다.
- 예산은 승인된 핵심 본문에만 적용한다. 일반 저장은 핵심 manifest 변경을 포함하지 않는다. 핵심 변경에는 정확한 본문과 선정에 대한 별도 사용자 확인이 필요하다.

## 비밀값과 종료

API 키·토큰·비밀번호 및 `<private>...</private>` 내용은 저장 입력에서 제외한다. 필요하면 비밀값 대신 `[REDACTED:VAR명]`으로 맥락만 남긴다. 서버의 scrub을 비밀값을 전달해도 된다는 허용으로 해석하지 않는다. 인증 확인을 위해 설정·환경·토큰을 출력하지 않는다.

저장이 완료되면 필요할 때만 한 줄로 알린다. 저장 가치가 없으면 아무 것도 하지 않는다. Stop 훅으로 이어진 평가에서 저장을 위해 또 다른 에이전트나 모델을 호출하지 않는다.
