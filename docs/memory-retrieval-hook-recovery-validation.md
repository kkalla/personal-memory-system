# Claude 검색 훅 — 보정 거부 후 복구 허용

2026-09-15 사용자가 `PreToolUse:mcp__memory__memory_search`에서 “검색 보정 차단 3회 한도에 도달했습니다. 작업 미완료.”로 진행이 종료됐다고 보고하고 차단 완화를 요청했다. 이번 수정은 그 요청에 따른 운영 제어 변경이다.

## 원인과 변경

`process_event`는 모든 `permissionDecision=deny`를 요청 단위 `denials`에 합산하고, 3회부터 `continue=false`를 붙였다. 검색어 형식 오류·프로젝트 이름을 ID로 사용한 오류·검색 전 변경 시도처럼 서로 다른 거부도 합산됐다. 따라서 잘못된 입력을 보정해 다시 시도할 경로까지 전체 턴 중단으로 닫혔다. 사용자가 보낸 문구는 이 분기와 일치하지만 실제 해당 세션에서 어떤 입력 세 개가 거부됐는지는 확인하지 않았다.

누적 거부를 전체 턴 종료로 확대하는 부분만 제거했다. 개별 잘못된 호출은 계속 deny하며 프로젝트 식별·인자 보정·결과 설명은 이어갈 수 있다. `denials` 기록과 기존 상태 형식은 유지하므로 이미 3회에 도달한 상태 파일을 삭제하거나 성공으로 조작할 필요가 없다.

유지하는 경계:

- 같은 문맥에서 실제 검색 최대 3회. 거부된 잘못된 인자는 실제 검색 횟수로 세지 않는다.
- 검색 범위·필터 변경, 잘못된 ID와 빈/여러 단어 쿼리는 계속 거부한다.
- 검색 미완료 상태의 Write/Edit/Bash/기억 저장 차단은 유지한다. 기존의 제한된 Git 조회 예외는 그대로다.
- 정상 0건은 검색 완료, 도구 오류는 미완료다. 오류나 거부를 성공으로 바꾸지 않는다.
- Stop 보정은 최대 1회이며 이후 검색 미완료를 기록한다. 상태 손상·요청 식별자 부재의 중단은 변경하지 않는다.

이전 [F1 계획](superpowers/plans/2026-09-14-memory-retrieval-t4-followup-plan.md)의 보정 한도 종료 정책 중 **거부 누적 3회에 따른 강제 종료**를 이번 사용자 요청으로 완화했다. 실제 검색 한도와 Stop 한도는 별도 유지한다. 에이전트가 같은 잘못된 호출을 반복하는 것 자체를 강제로 끝내지는 않으므로 반복 도구 거부 비용은 남을 수 있다. 현재 보정 불가능하면 에이전트는 미완료 이유를 설명하고 종료해야 한다.

## 검증과 운영 반영

공개 Python CLI에 합성 훅 이벤트를 보내는 기존 테스트를 사용했다. 모든 상태는 임시 디렉터리에 생성하며 실제 세션 상태·기억·인증 정보는 사용하지 않았다.

1. 검색 전 Write 3회 거부, 잘못된 검색 입력 3회 거부, 정상 검색 3회 뒤 추가 검색 3회 거부를 각각 재현했다. 수정 전에는 세 테스트가 모두 위 `continue=false`와 동일 중단 문구 때문에 실패했다.
2. 최소 수정 뒤 검색 훅 테스트 20개가 통과했다. 거부 후 올바른 검색으로 복구, 검색 미완료 변경 거부, 실제 검색 한도 보존, 정상 0건 결과 보존을 확인했다.
3. `python3 -m unittest discover -s tests -p 'test_*.py' -q`: 전체 63개 통과. `git diff --check` 통과. 과거 모델 평가 점수나 실패 기록은 변경하지 않는다.

Claude 전역 설정의 6개 관련 이벤트가 저장소의 `scripts/memory_retrieval_hook.py`를 직접 실행하는 것을 읽기 전용으로 확인했다. 따라서 별도 설정 변경이나 배포 복사 없이 다음 훅 프로세스부터 수정 코드가 사용된다. 이미 끝난 턴을 자동 재개하지는 않으므로 사용자는 새 메시지로 이어갈 수 있다. 실제 Claude 모델 실행은 추가하지 않았으며 자연어 보정 준수까지 검증했다고 보고하지 않는다.

프로젝트 등록은 별도 MCP 작업이며 이 수정으로 프로젝트를 자동 등록하거나 후보 기억을 확정하지 않는다.
