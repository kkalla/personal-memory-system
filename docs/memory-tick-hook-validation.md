# memory-tick 저장 스킬·Stop 훅 보강 — 2026-09-14

사용자 “좋다. 훅 변경도 승인”에 따라 기존 훅 수정 금지 경계를 이번 보강에 한해 해제했다. 기존 사용자 변경인 60분 간격은 유지했다. [운영 적용 계획](superpowers/plans/2026-09-14-memory-retrieval-operations-plan.md)의 실제 볼트·전역 설정 설치는 아직 수행하지 않았다.

## 변경

- 기존 `stop-hook-throttle.sh` 경로와 실행 권한은 유지하고 표준 라이브러리만 사용하는 `stop_hook.py`를 호출한다. 추가 패키지를 설치하지 않는다.
- Claude/Codex 공통으로 이벤트의 `session_id`를 hash한 세션별 상태 파일을 사용한다. 기본 상태 경로는 `~/.local/state/personal-memory/memory-tick`, 격리 실행은 `MEMORY_TICK_STATE_DIR`로 지정한다. 이전 `MEMORY_TICK_MARKER`와 공유 마커는 더 이상 사용하지 않으며 기존 파일은 삭제하지 않았다.
- 60분은 저장 성공이 아닌 평가 요청 간격이다. 새 세션은 첫 Stop에서 평가할 수 있다. 따라서 과거 전역 타이머보다 여러 세션의 평가 횟수가 늘 수 있으며, 이는 다른 대화가 누락되지 않도록 승인된 세션 분리의 결과다.
- 같은 세션의 동시 호출은 파일 잠금으로 한 번만 평가를 요청한다. 잠금 대기는 하지 않는다. 상태 inode를 유지하고 기록·동기화 성공 후에만 block 응답을 출력한다. 이 잠금은 훅 평가 요청에만 적용하며 MCP 볼트 동시 쓰기 잠금이 아니다.
- 잘못된 JSON, 객체가 아닌 입력, 비어 있거나 잘못된 session_id, 재귀 평가, 잘못된 재귀 플래그, 상태 생성/기록 실패, 잠금 경합에는 무출력·exit 0이다. session_id가 없는 환경은 공유 타이머로 후퇴하지 않고 평가를 생략한다. 실제 CLI 이벤트 호환 확인은 운영 적용의 점검 항목이다.
- 스킬 경로는 실행 파일 옆 SKILL.md의 실제 절대 경로로 제공한다. Codex가 Claude 전용 스킬 링크에 의존하지 않는다.
- 저장 스킬은 기존 100줄 인덱스 정리, 직접 Write, 자동 삭제 지침을 제거했다. 기존 계약의 전체 목록 보존·범위/상태 결정·후보 격리·MCP의 scrub과 쓰기 검증·부분 실패 확인을 사용한다. 현재 쓰기 제한은 Stop 요청으로 해제되지 않는다.
- 저장 가치가 있어도 MCP가 없으면 직접 볼트 쓰기로 우회하지 않고 미완료로 종료한다. **현재 전역 memory MCP 연결이 아직 없어, 연결 전 자동 저장은 미완료로 남을 수 있다.** 이것을 운영 적용 완료로 보고하지 않는다.

## RED → GREEN

1. malformed JSON의 공개 셸 입력 테스트에서 기존 훅이 block을 출력해 FAIL. JSON 검사 후 통과.
2. 두 번째 세션의 첫 평가 테스트에서 기존 공유 마커 때문에 응답이 없어 ERROR. 세션별 상태로 바꿔 통과.
3. 만료 상태를 다른 프로세스가 잠근 동안의 호출 테스트에서 평가 요청이 발생해 FAIL. 비차단 파일 잠금 적용 후 무출력, 잠금 해제 후에는 정상 요청.
4. 반환된 스킬 경로 테스트에서 기존 Claude 전용 경로가 나와 FAIL. 실행 위치에서 공통 스킬 경로를 계산한 뒤 통과.

추가 검증은 기존 60분 간격, 재귀/식별자 오류, 상태 기록 실패 후 복구, 동일 세션 8개 동시 subprocess의 평가 요청 1개를 확인했다. 테스트는 모두 임시 상태 디렉터리를 사용하며 실제 상태·볼트에 쓰지 않는다. 문서 문구만 반복하는 테스트는 추가하지 않았다.

## 적용 상태와 복구

두 환경의 기존 전역 Stop 설정이 저장소의 셸 경로를 직접 참조하며, Claude 스킬 링크도 저장소를 가리킨다. 따라서 이번 파일 수정은 다음 훅 호출·스킬 읽기부터 영향을 준다. MCP 등록·새 SessionStart·검색 지침·프로젝트 등록·핵심/레거시 전환은 남아 있다. 전역 설정 파일, 실제 볼트, launchd는 수정하지 않았고 사례 지식 자동 추출도 추가하지 않았다.

변경 전 셸의 SHA-1은 `405495a60da413ec38c0b6e91c02e663c0e95c40`이었다. 원본 스킬·테스트와 사용자 60분 변경이 포함된 셸 스냅샷은 `/private/tmp/memory-tick-before-20260914/manifest.json`에 경로·hash를 기록했다. 셸은 HEAD의 30분 버전에 기존 60분 변경을 반영해 재구성하고, 작업 전 확인한 SHA-1과 일치함을 검증했다. 임시 백업의 영구 보존을 보장하지 않는다.

복구 시 변경 대상 파일에 이후 편집이 없는지 확인하고 해당 스냅샷만 복원한다. Git 부모 커밋의 셸을 그대로 복원하면 30분으로 되돌아가므로, 스냅샷이 없으면 부모 버전에 60분을 반영하고 위 SHA-1을 확인해야 한다. 전역 설정/실제 볼트를 과거 상태로 덮어쓰지 않는다. 새 세션 상태 파일은 자동 정리하지 않으며 평가 중 삭제하면 중복 호출이 생길 수 있으므로 별도 정리는 비활성 상태에서 검토한다.
