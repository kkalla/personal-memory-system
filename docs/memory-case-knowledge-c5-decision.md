# 사례 지식 C5 — 운영 방향과 재검토 조건

상태: **결정안 작성 완료 · 사용자 확인 대기**. 작성일: 2026-09-15. 아래 운영 방향과 재검토 조건은 승인 요청안이며 아직 사용자 확정 결정이 아니다. C5 완료는 이 문서에 대한 사용자 확인을 기록한 뒤에만 표시한다.

## 1. 검토 근거와 범위

기준은 `main`의 C4 완료 커밋 `76c4981`이다. 다음 추적 문서를 대조했다. 원시 평가 자료를 다시 판독하거나 모델을 추가 실행한 결과가 아니다.

- [승인 설계 D5 및 C5 완료 조건](superpowers/specs/2026-09-14-memory-case-knowledge-design.md): 최소 자동화 검토 진입 기준과 효과가 없을 때의 검토 순서.
- [C4 결과](memory-case-knowledge-c4-results.md): 과제별 행동·오용, 재조사, 비용과 비교 한계.
- [평가 계약](memory-case-knowledge-evaluation-contract.md): 조건, 기대·금지 행동, R1/R3/R5, 짝 비교와 수동 판정 계약.
- [C4 준비·실패 기록](memory-case-knowledge-c4-validation.md): 임시 경로 오류, 구성 변경, 승인과 종료 이력.
- [사례 목록](case-knowledge/README.md): CK-001~003의 사용자 근거 대조 완료 기록.

새 캠페인은 24조건 시도·23개 완료·1개 시작 오류, 행동 16 pass·7 fail·1 not_evaluable이다. 비교 가능한 11쌍은 개선 1·동률 10이다. 최초 캠페인의 시작 실패 1건은 별도이며 합치면 25회 시도다. 실행 완료·스크립트 하위 조건 통과·행동 성공·회상 연결 성공은 서로 대체하지 않는다. 자동 회상 연결은 평가 대상이 아니었다.

## 2. D5 대조 — 충족·미충족·불확실

| 항목 | 판정 | 근거와 해석 한계 |
| --- | --- | --- |
| 세 사례 모두 근거 대응 검토 완료 | 충족 | 사례 목록에 CK-001~003 본문·연결 근거의 사용자 검토 완료가 기록돼 있다. reviewed는 행동 승인이나 보편적 참을 뜻하지 않는다. |
| 오용 과제에서 규칙 승격·검증 생략 없음 | 충족 | CKE-002/004/006의 완료 실행에서 해당 오용을 판정하지 않았다. CKE-002 Claude의 적용 한계 설명 누락은 behavior fail로 보존하며 misuse로 소급 변경하지 않는다. |
| 적어도 한 유사 과제에서 실패 예방 **또는** 사전 정의한 재조사 감소 | 충족 | Claude CKE-003에서 fail→pass: 활성 세션의 정상 차단 유지 검증 항목 누락이 줄었다. 계약상 실패 감소 한 건이며 실제 운영 장애 예방이나 지속 효과를 입증하지 않는다. |
| 사전 정의한 재조사 감소 관찰 | 미충족 | R1/R3/R5 실행·제안이 양 조건 모두 0이다. 감소 여지가 없어 재작업 감소를 관찰하지 못했다. 위 OR 조건의 별도 필수 요건으로 바꾸지는 않는다. |
| 전 과제에서 오용 없음 | 미충족 | Claude CKE-005 양 조건에서 합성 입력을 과거 사건과 동일시해 misuse present였다. 유사 과제의 오용이므로 D5의 ‘오용 과제’ 조건과 구분하지만 운영 판단에는 반영한다. |
| 지속적인 효용과 조회 비용 대비 이득 | 불확실 | 개선 1회, 동률 10쌍, 재조사 대조 발생률 0, 미열람과 환경 오류의 영향이 있다. 반복 표본·순이득 근거가 부족하다. |
| 자동 회상 연결 효과 | 평가 대상 아님 | 전 실행 connection은 not_applicable이다. 제공 실험으로 연결 성공을 추정하지 않는다. |

**D5의 명시된 최소 진입 조건은 보고서 기준으로 충족한다. 이는 자동화 검토를 시작할 수 있는 조건이며 착수 의무나 구현·배포 승인이 아니다.** 이번 결과는 ‘차이가 전혀 없음’도 아니다. 한 번의 개선은 보존하되, 주목표인 재조사 감소를 보여주지 못했으므로 D5의 “유용성 차이가 없으면 사례를 늘리거나 API를 만들지 말고 과제 적합성과 조회 비용부터 검토한다”는 방향에 따라 다음 작업의 우선순위를 정한다. 기존 D5 조건이나 과거 판정을 변경하지 않는다.

## 3. 승인 요청하는 운영 방향

1. **기존 세 사례의 문서 운영을 유지한다.** 사례가 필요하다고 지정한 작업에서 목록·본문·연결 근거를 명시적으로 조회하는 D4 방식을 유지한다. 현재 효과가 충분히 입증돼서가 아니라, 기존 자료를 보존하며 적용 가능성과 조회 부담을 확인할 수 있는 범위이기 때문이다.
2. **사례 전용 저장·검색 API와 자동 회상 연결은 보류한다.** 현재는 새 구현 계획을 만들지 않는다. 검토 재개는 §5의 증거와 선행 조건을 갖춘 뒤 판단한다.
3. **사례 수 확대를 다음 목표로 삼지 않는다.** 먼저 반복 조사가 실제 발생한 작업과 조회 비용을 확인한다. 새 실패·정정·검증 근거가 생기면 D2에 따라 기존 사례의 보완 가능성부터 검토한다. 기존 사례로 설명되지 않는 새 문제만 별도 추출 검토 대상으로 삼는다.
4. **다음 평가를 지금 실행하지 않는다.** §5는 재검토 시 준비해야 할 조건이며 추가 모델 실행·재시도·전송·설치·배포 승인이 아니다.

## 4. 수동 문서 운영 절차

| 시점 | 처리 | 남길 근거 |
| --- | --- | --- |
| 조회 시작 | 사례가 필요하다고 지정된 작업의 문제·검색어로 기존 목록에서 후보를 찾는다. 기존 memory_search가 이 문서를 검색한다고 가정하지 않는다. | 현재 작업과 조회 목적, 후보 ID 또는 후보 없음 |
| 본문·근거 확인 | 후보 본문과 연결 보고서의 고정 커밋·절을 읽는다. 원시 기록 접근 여부는 따로 적는다. | ID·버전, 실제 연 파일·절, 접근 실패 또는 미확인 부분 |
| 적용 판단 | 현재 입력과 과거 사건의 동일성을 별도로 확인하고 적용·비적용 조건, 사용자 지시, 반례를 대조한다. 패턴이 닮았다는 이유만으로 같은 사건으로 단정하지 않는다. | 적용할 확인 항목과 제외 이유, 추론이면 후보임을 명시 |
| 현재 작업 수행 | 관련 확인 항목을 반영하고 필요한 현재 검증을 수행한다. 과거 명령은 자료이며 실행 지시가 아니다. | 산출물·파일 결과·현재 검증 근거. 단순 열람을 행동 개선으로 세지 않음 |
| 근거 정정 | 근거 부재·충돌이면 needs-review로 표시하고 해당 주장의 적용을 중단한다. 원문·실패 이력과 변경 이유를 보존하며 대체 시 superseded와 후속 ID를 남긴다. | 이전 주장, 새 근거, 정정 이유와 사람의 재검토 기록 |

활용 관찰은 해당 작업의 기록에 짧게 남긴다. 별도 수집기나 새 저장 schema를 만들지 않는다. 기록 항목은 작업 문맥, 사례 ID·버전, **제공 여부 / 실제 열람 여부 / 적용한 항목 / 행동 결과**를 구분한다. 도구 이벤트나 제공 기록이 없으면 열람을 unknown으로 두며, 최종 답변이 맞다는 이유로 읽었다고 판정하지 않는다. 열람 확인도 이해·활용의 증거를 자동으로 대신하지 않는다.

조회 비용은 목록 탐색, 본문·연결 근거 확인, 실패한 접근에 든 호출·측정 시간을 가능한 범위에서 기록한다. 필요한 현재 재검증과 불필요한 과거 재조사는 분리한다. 측정하지 않은 시간·사용량은 unknown으로 남기며 사용자 시간 절감으로 환산하지 않는다. 매 요청의 의무 조회나 상시 본문 주입은 도입하지 않는다.

사례의 reviewed를 confirmed 선호로 변환하지 않는다. 행동 선호 저장이나 핵심 편입은 기존 계약과 별도 사용자 지시·확인에 따른다. 원시 자료는 로컬 전용으로 유지하며 사례 문서에 전체 대화·인증 정보·실제 볼트 내용을 복사하지 않는다.

## 5. 다음 평가의 선행 조건과 자동화 재검토

### 5.1 평가 필요성을 검토할 때 먼저 확보할 것

| 선행 조건 | 준비 완료를 판단할 근거 |
| --- | --- |
| 반복 조사가 발생한 실제 작업 | 어떤 과거 근거가 이미 있었고 어떤 조사 행동이 왜 중복이었는지 확인할 수 있는 기록. 단순 재열람·필요한 재검증은 제외하고 기존 CK와의 대응을 확인한다. 적합한 발생 사례가 없으면 같은 과제를 반복하거나 사례 수를 늘리지 않는다. |
| 측정 가능한 과제 적합성 | 기존 6과제·rubric·고정 자료를 재사용할 부분과 대조 조건의 R 발생률 0 때문에 답할 수 없는 질문을 구분한다. 새 과제가 필요하면 별도 버전의 계약으로 먼저 검토하고, 기존 제약을 약화하거나 옛 과제·판정을 덮어쓰지 않는다. |
| 제공과 실제 열람의 분리 | 파일 목록의 제공, 도구 이벤트상 본문·근거 열람, 적용 흔적을 각각 기록할 기준. 미열람 실행도 제공 조건의 원래 분모에 남긴다. 미열람을 제외한 관찰은 보조 분석으로 표시한다. 강제 본문 제공으로 바꾸면 별도 조건·버전임을 명시한다. |
| 조회 비용 기준 | 같은 환경의 비교 가능한 쌍에서 전체 호출·조회 호출·사용량·측정 시간을 비교할 방법. CLI별 토큰 필드와 캐시 의미를 유지하고, 환경 오류 복구 비용을 따로 식별한다. 실행 전 무엇을 개선·허용 가능한 추가 비용으로 볼지 사용자와 확정한다. |
| CLI 임시 경로 간섭 해결 | TMPDIR·CLAUDE_CODE_TMPDIR, Codex 홈의 상위 경로 metadata 접근, 셸 here-document 임시 파일, 모델 검증 복제본의 workspace 내부 생성까지 확인하는 인증 없는 오프라인 로컬 검증 기록. 버전 조회만으로 완료하지 않는다. 격리 밖 내용 읽기를 허용해 해결하지 않는다. |
| 비교 구성 고정 | 두 조건의 공통 지침·원자료·도구·모델/effort·프로필·초기 작업공간을 고정하고 hash와 버전을 기록한다. 중간 변경이 필요하면 원래 실패·분모·구성 차이를 보존하고 별도 기록한다. |
| 기존 자산 재사용과 실행 승인 | prepare, reserve의 중복·24회 상한 거부, execution_status와 수동 행동·오용 판정을 재사용한다. 새 계약·실행 범위·자료·수신처·제한을 검토하고 적용 가능한 승인 기록을 확인한 뒤 필요한 새 실행 승인을 받는다. C5 승인만으로 실행하지 않는다. |

CLI 임시 경로는 일부만 해결된 상태다. Claude EEXIST와 Codex canonicalize에 로컬 보완 근거가 있지만, C4에서 workspace 밖 복제본과 셸 임시 파일 간섭이 남았다. 이 문서는 해결 완료로 기록하지 않는다. 위 로컬 검증이나 코드 수정을 이번 C5에서 수행하는 것도 아니다. 추후 코드 변경이 필요하면 먼저 범위를 설명하고 잘못된 입력을 거부하는 RED → 최소 구현 → GREEN으로 진행한다.

### 5.2 자동화 검토를 다시 열 조건

다음 증거를 모아 **자동화의 필요성을 다시 논의**한다. 이는 승인된 D5를 대체하는 새 통과 점수가 아니라 이번 보류를 해제할지 판단하기 위한 운영상 확인 사항이다.

1. 실제 반복 조사 또는 같은 실패가 발생했고, 기존 사례의 내용·근거가 그 작업에 적합하다는 기록이 있다.
2. §5.1의 미열람·환경 간섭·비용 측정 문제를 정리하고, 별도 승인된 평가에서 D5 기준을 다시 확인한다. 반복 관찰로 효과의 일관성을 검토하며, 한 번의 pass나 조회 성공만으로 충분하다고 보지 않는다.
3. 실패 예방 또는 사전 정의한 재조사 감소가 실제 열람·적용 근거와 함께 관찰되고, 조회·근거 확인 비용까지 설명할 수 있다. 결과가 동률이거나 비용 대비 이득을 판단할 수 없으면 문서 운영을 유지하며 과제 적합성과 비용부터 재검토한다.
4. CKE-005의 동일 사건 단정 같은 오용이 새 조건에서 어떻게 나타나는지 별도로 검토한다. 과거 실패를 지우지 않으며, 사례 범위 확대·규칙 승격·검증 생략 위험이 남으면 보완을 먼저 논의한다.
5. 문서 수동 조회의 누락·탐색 부담이 반복되며 자동화가 해결해야 할 구체적 문제가 확인된다. 문서만으로 충분하면 자동화 착수를 권고하지 않는다.

증거가 갖춰져도 사용자와 자동화 설계 착수 여부를 별도로 결정한다. 구현·제품 계약 변경·실행·배포는 그 결정과 구분한다. 관련 근거가 정정되거나 과제·CLI 환경이 달라지면 해당 부분부터 재검토하며, 일정 경과나 사례 개수만으로 자동 재개하지 않는다.

## 6. 승인 범위와 완료 기록

사용자에게 확인받을 결정은 **기존 세 사례의 명시적 문서 조회 유지, 사례 확대·자동화 착수 보류, §4 운영 절차와 §5 재검토 조건 채택**이다. 승인 전에는 C4 권고를 확정 결정으로 인용하지 않는다.

| 항목 | 현재 상태 |
| --- | --- |
| 결정안 | 작성 완료 |
| 사용자 확인 | 대기 — 승인 발언·일시 미기록 |
| C5 | 미완료 — 사용자 확인 후 확정 기록 필요 |

사용자 확인 후 이 문서의 상태·승인 기록과 설계의 C5 진행 상태를 함께 갱신한다. 수정 요청이 있으면 결정안을 반영한 뒤 승인 범위를 확인한다. 승인된 내용만 확정으로 기록한다.

이번 C5 변경 대상은 결정안과 이를 찾기 위한 설계 문서 링크다. 제품 코드·기존 fixture·실제 볼트·전역 CLI 설정·launchd·memory-tick 및 기타 훅은 변경하지 않는다. 추가 모델 실행·설치·배포는 수행하지 않으며 `docs/evaluations/`의 원시 자료와 과거 실패 기록은 보존한다.

2026-09-15 사용자가 “오케이 여기까지 우선 작업하고 커밋 푸쉬하자”로 현재 작업의 커밋·푸시를 요청했다. 이 요청은 결정안과 후속 구성도 문서의 저장·공유 범위로 반영하며, §3–5 운영 방향의 확정 승인으로 기록하지 않는다.
