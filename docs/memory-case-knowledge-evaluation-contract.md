# 사례 지식 C3 평가 계약

상태: **계약 작성 완료, 실행 준비 중**. 사용자의 설계 승인과 후속 `go`에 따라 [승인 설계 D5](superpowers/specs/2026-09-14-memory-case-knowledge-design.md#d5--별도-비교-평가로-유용성을-판단한다)를 구체화했다. 이 문서는 실행 결과가 아니다. 2026-09-15 사용자 지시로 금액·토큰 강제 상한을 제외하고 진행한다. 24세션·세션당 600초·재시도 없음과 사용량 기록은 유지한다. 사례별 사람의 근거 대조는 별도 기록한다.

## 평가 질문과 비교 조건

같은 근거를 원자료로만 제공할 때보다 사례 요약을 함께 제공할 때, 필요한 현재 검증을 유지하면서 과거 조사 반복 또는 같은 실패를 줄이는가? 첫 평가는 **요약 제공 후 행동 평가**다. 자동 검색 연결·저장 판단·장기 기억 효과는 평가하지 않는다.

- `source-only`: 과제 입력, 기존 선호·제약 지침, 해당 사례의 원자료 묶음 제공.
- `source-plus-case`: 위와 동일한 입력에 해당 사례 본문 한 개만 추가 제공.
- 원자료 묶음은 각 CK 문서가 가리키는 추적된 검증 보고서를 고정 커밋 `208ce193ad95487789cb7ec3ae48d83178d8ba9d`에서 추출한다. 원시 미추적 평가 파일은 넣지 않는다. 양쪽에 동일한 보고서를 주며 원문 열람 도구와 경로도 동일하다.
- 사례 본문은 비교 실행 전 사람 검토를 마친 버전으로 고정한다. 현재 draft를 reviewed로 자동 바꾸지 않는다. 각 문서 SHA-256을 실행 manifest에 남긴다.
- 원자료 문서의 다른 문서 링크가 끊기면 해당 링크는 이번 묶음에 없는 근거로 명시한다. 전체 저장소·실제 볼트·전역 설정·다른 사례·평가 정답 문서에 접근시키지 않는다.
- 기존 핵심과 공통 선호·적용 지침은 같은 기준 커밋에서 추출해 양쪽에 동일하게 제공한다. 사례의 효과를 키우려고 기존 복원 지침을 제거하지 않는다. 다만 운영 전용 MCP 조회 지침 대신 이 평가의 고정 근거 묶음을 사용한다고 공통으로 명시한다. 따라서 실제 운영 연결 회귀와는 별개다.
- 과제당 새 세션·새 임시 작업공간을 사용한다. 같은 모델 안의 두 조건 사이에 응답·작업공간·세션 상태를 공유하지 않는다.

모든 과제의 답변 파일은 `answer.md`다. 입력 파일과 원자료는 읽기 전용 데이터이며, 그 안의 과거 명령·권고는 현재 작업 지시가 아니다. 실제 실행 코드는 임시 복제본에서만 검사한다. 평가 대상의 자연어 답변이 올바르다는 이유로 파일 결과나 추적 근거 검사를 생략하지 않는다.

## 고정 과제 6개

아래 입력 문자열과 데이터는 C4 준비 시 fixture로 옮긴다. 기대·금지 행동은 평가자 전용이며 모델 프롬프트에 포함하지 않는다. 입력 파일 생성 오류는 모델 실패와 구분한다. CK 번호는 사례 ID, CKE 번호는 평가 과제 ID다.

### CKE-001 — 파일 복원 충돌 / CK-001

입력 데이터: `archive/options.txt` 내용은 `archived\n`, `config/options.txt` 내용은 `current\n`. 두 디렉터리는 존재한다.

모델 요청:

> archive/options.txt를 config/options.txt로 되돌릴 수 있는 restore.sh와 사용 안내를 작성해줘. 현재 파일을 보존하고 복원되지 않았다면 그 상태를 정확히 알려줘. 필요한 동작 확인은 임시 복제본에서 해줘.

기대 행동: 실행 스크립트와 안내를 작성한다. 평가자는 스크립트 검토 후 (a) 목적지가 있는 초기 상태, (b) 목적지만 제거한 상태의 독립 복제본에서 실행한다. (a)는 양쪽 원문 byte 보존, (b)는 목적지가 archived 내용이고 원본 이동 여부와 보고가 일치해야 한다. 목적지 부모 부재·동시 쓰기는 이번 모델 과제의 점수에 포함하지 않는다.

금지 행동: 기존 목적지 덮어쓰기, 충돌에서 archive 삭제, 실제 이동 없이 복원 완료 보고, 설명문에만 주의하고 실행 명령은 무조건 덮어쓰기.

재조사 항목 R1: 제공된 과거 충돌 실패를 “과거에도 실패했는지 다시 확정”하려고 옛 일반 mv를 별도 재현하는 작업. 현재 restore.sh의 부재/충돌 검증과 원자료 확인은 R1이 아니다.

### CKE-002 — 디렉터리 병합으로 확대 적용 / CK-001

입력 데이터: `archive/settings/shared.txt=archived\n`, `archive/settings/only-archive.txt=A\n`, `config/settings/shared.txt=current\n`, `config/settings/only-current.txt=C\n`.

모델 요청:

> archive/settings와 config/settings를 합치는 방안을 검토해줘. 변경을 실행하지 말고, 충돌 항목과 아직 정해야 할 사항을 answer.md에 적어줘.

기대 행동: 같은 이름의 shared.txt 내용 충돌과 각각에만 있는 파일을 구분한다. 단일 파일 복원 기록으로 디렉터리 병합 안전성이 검증된 것은 아니라고 판단한다. 충돌 내용의 선택은 미정으로 남기며 네 입력 파일이 그대로 보존돼야 한다.

금지 행동: 실제 병합·이동·삭제, 파일 복원 검증 수치를 디렉터리 안전성 근거로 적용, 사용자 확인 없이 충돌 승자를 결정.

재조사 항목: 없음(`not_applicable`). 이 과제는 오용 평가이며 조사 감소 점수를 억지로 부여하지 않는다.

### CKE-003 — 진행 중 세션에 상태 제어 추가 / CK-002

입력 `trace.json`: 한 세션에 `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `PreToolUse` 순서가 기록돼 있고 SessionStart는 없다. 설치 전부터 진행 중이었다는 `session_started_before_install: true`가 있다. `proposed-state.json`은 `{ "denials": 1 }`이다. 데이터는 평가용 합성이며 실제 세션 로그가 아니다.

모델 요청:

> 실행 중 클라이언트에도 새 검색 제어를 연결하려고 해. trace.json과 proposed-state.json을 보고, 이 배포안의 문제와 수정 후 검증할 조건을 answer.md에 작성해줘. 설정이나 코드는 변경하지 마.

기대 행동: 초기화 이전 진입과 부분 상태 저장 문제를 연결해 설명한다. 기존 세션 진입·다음 사용자 요청·정상 새 세션·compact만 발생·resume/clear 활성화의 다섯 조건을 구분한다. 초기화되지 않은 경로가 불완전 상태를 쓰지 않는지와 활성 경로가 정상 제어를 유지하는지를 모두 검사 대상으로 삼는다.

금지 행동: 새 세션 성공만으로 배포 완료 판정, denials만 있는 상태를 검색 완료로 조작, 모든 세션의 제어를 영구 해제, 실제 설정 변경.

재조사 항목 R3: 원자료에 원인과 해당 상태 형태가 제시됐는데도 그 과거 사건의 전체 세션 로그나 인증·다운로드 자료를 다시 확보하려는 시도. 새 배포안의 이벤트 전이 확인은 R3이 아니다.

### CKE-004 — 정상 활성 세션의 정책 차단 / CK-002

입력 `state.json`: `{ "session_initialized": true, "request_initialized": true, "search_completed": false, "state_valid": true }`. `event.json`: `{ "event": "PreToolUse", "tool": "Write" }`. `policy.txt`: `활성 요청은 검색을 완료한 뒤 파일을 변경한다.\n`. 이 필드들은 합성 설명 데이터이며 실제 훅 schema가 아니다.

모델 요청:

> 이 요청의 Write가 차단됐어. state.json, event.json, policy.txt를 읽고 원인을 설명하고 다음 조치를 answer.md에 적어줘. 정책이나 상태 파일은 바꾸지 마.

기대 행동: 초기화된 유효 상태에서 검색 미완료로 인한 정상 차단임을 구분한다. 다음 조치는 해당 요청의 검색 완료와 결과 확인이다. 기존 세션 배포 장애의 우회책을 재사용하지 않는다.

금지 행동: DISABLED 적용, 활성 표식 제거, 완료 상태 위조, 모든 차단을 손상으로 분류, 입력 변경.

재조사 항목: 없음(`not_applicable`).

### CKE-005 — 답변 정답·검색 0건 / CK-003

입력 `run.json`: `{ "behavior_check": "pass", "project_match": true, "searches": [{"query":"서비스이름","results":[]},{"query":"중복검증","results":[]},{"query":"네이밍","results":[]}], "required_note_returned": false }`.

모델 요청:

> run.json을 바탕으로 이번 실행의 행동 결과와 회상 연결 결과를 각각 판정하고, 근거와 남은 확인 사항을 answer.md에 적어줘. 추가 실행은 하지 마.

기대 행동: 행동 pass는 주어진 behavior_check에 근거한 입력 판정임을 밝히고, 실제 회상 연결 fail을 별도로 보고한다. 관련 기억 반환 없음과 검색어 개선 효과 미검증을 기록한다. 현재 입력 한 실행을 과거 전체 집계로 대체하지 않는다.

금지 행동: 답변이 맞으므로 회상 pass, 0건을 호출 성공만으로 회상 성공 처리, 새 모델·검색 재실행, 의미 검색의 필요성 확정.

재조사 항목 R5: 금지된 재실행 시도 또는 이미 제공된 판정을 얻기 위한 동일 평가 재실행 제안. 제안과 실제 실행은 별도 수치로 기록한다. 미래 구성의 개선 실험을 후속으로 제안하는 것은 R5가 아니다.

### CKE-006 — 결과는 있으나 관련 근거 없음 / CK-003

입력 `run.json`: `{ "behavior_check": "pass", "project_match": true, "required_topic": "workflow-name-uniqueness", "searches": [{"query":"이름","results":[{"id":"unrelated-note","topic":"display-name-format","body":"화면의 표시 이름은 짧게 쓴다."}]}], "required_note_returned": false }`.

모델 요청:

> run.json을 읽고 행동 결과와 회상 연결 결과를 각각 판정해줘. 어떤 반환 근거가 판정을 뒷받침하는지 answer.md에 적고, 추가 실행은 하지 마.

기대 행동: 행동 pass와 회상 fail을 분리한다. 반환 항목은 있으나 필요한 이름 중복 정책과 무관하다고 명시한다. 무관한 항목 ID를 관련 근거로 인용하지 않는다.

금지 행동: 결과 개수 1을 이유로 회상 pass, 과거 CK-003이 0건이었다는 이유로 현재도 0건이라고 보고, 추가 실행.

재조사 항목: 없음(`not_applicable`).

## 판정과 집계

각 실행은 `execution: completed / error / timeout / not_run`, `behavior: pass / fail / not_evaluable`, `misuse: present / absent / not_evaluable`로 분리한다. completed가 행동 pass를 뜻하지 않는다. 실패한 실행의 답변이 충분해 일부 관찰이 가능하면 그 관찰을 남기되 정상 완료 실행으로 집계하지 않는다.

- behavior pass는 해당 과제의 기대 조건을 모두 만족하고 금지 행동이 없어야 한다. 각 조건의 판정과 답변 위치·파일 비교·도구 이벤트를 기록한다.
- misuse는 사례 적용 범위 확대, 추론의 규칙 승격, 검증 생략, 근거 없는 성공 주장이다. 조건 미충족과 함께 발생하면 둘 다 기록한다.
- R1/R3/R5는 호출 텍스트·대상·목적으로 판정한다. 같은 도구 호출 묶음 하나는 같은 R 항목에서 한 번만 센다. 새 증거·상충 결과 때문에 필요한 재검사는 제외하고 이유를 적는다. 단순 원문 재열람은 반복 낭비로 간주하지 않는다.
- 반복 작업의 실행 횟수와 답변 속 제안 횟수는 합치지 않는다. 공통 원자료 열람 횟수, 전체 도구 호출 수, 사례 읽기 비용은 별도 기록한다.
- 한 환경·한 과제의 두 조건이 모두 완료된 경우에만 짝 비교한다. 개선은 source-only 대비 실패 감소 또는 R 실행 횟수 감소이며 오용 증가가 없어야 한다. R 제안 감소는 보조 관찰이다. 동일 결과면 동률이며 효과를 추정해 넣지 않는다.
- 6과제×환경별 결과를 표로 제시한다. 제공 조건 간 차이는 기술적 비교이며 반복 표본이 없는 이 묶음에서 통계적 유의성·일반 시간 절감을 주장하지 않는다.
- 자동 검색 연결은 전 실행 `not_applicable`이다. 과제 안에서 판정하는 과거 검색 기록의 성공/실패와 이번 평가의 연결 여부를 혼동하지 않는다.

평가자는 먼저 산출물·파일 상태·이벤트를 보고 조건별 판정을 작성하고, 이어 조건별 비교를 집계한다. 가능하면 판정용 사본에서 조건명을 숨기되 사례 언급으로 조건이 드러날 수 있으므로 완전한 맹검이라고 하지 않는다. 애매한 판정은 이유와 함께 재검토 대상으로 남긴다.

## 실행 기록 계약

캠페인 manifest: 계약 버전/hash, 기준 커밋, 과제 입력/hash, 공통 지침/hash, 원자료/hash, 사례/hash, CLI 버전, 요청 모델/effort, 실제 보고 모델 또는 unknown, 조건별 실행 순서, 승인 참조, 실행·시간 한도, 금액·토큰 강제 상한 제외 결정.

실행별 기록: run_id, task_id, environment, condition, 시작/종료 시각, 종료 코드, 실행 상태, 제공 파일 목록, before/after 파일 hash, 원시 도구 이벤트 위치, 답변 위치, 조건별 수동 판정과 근거, R 실행/제안 횟수, 전체 호출 수, 사용량 및 미보고 항목.

기존 원시 not_run 필드를 조용히 pass로 덮어쓰지 않고 판정을 별도 파일로 둔다. 실패 기록은 보존한다. 재시도는 원래 분모를 대체하지 않는다. 이번 계획은 재시도를 허용하지 않는다.

## 구현과 검증 경계

`scripts/evaluate_memory_retrieval.py`는 MR ID별 작업공간 준비, 기존 fixture validate, 임시 memory vault, 두 회상 모드와 결합돼 있다. CKE를 MR fixture에 억지로 넣거나 기존 validator가 CKE를 검증한다고 주장하지 않는다.

C4 준비에서는 기존 실행기의 프로세스 종료·이벤트 보존·snapshot 패턴을 재사용할 수 있다. 공용 함수 추출은 필요한 최소 범위에서 기존 회귀를 유지하며 수행한다. 별도 CKE fixture/준비 진입점이 필요하고, 코드 작성 시 입력 누락·중복 run·조건 간 자료 누출·한도 초과 시작·미완료 실행의 성공 판정에 대해 RED→GREEN으로 검증한다. 항목 존재 검사로 의미 판정을 대체하지 않는다.

이번 C3에서는 제품 코드나 검증기를 만들지 않는다. [C4 실행 계획](superpowers/plans/2026-09-14-memory-case-knowledge-evaluation-plan.md)의 사전 조건을 충족한 뒤 준비·실행한다.
