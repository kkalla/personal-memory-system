# 사례 지식 C4 준비·첫 실행 기록 — 2026-09-15

사용자가 금액·토큰 강제 상한을 제외하고 진행하도록 지시했고, 이어 CK-001~003의 본문·연결 근거에 대해 “검토 완료”라고 답했다. 세 사례를 reviewed로 기록했다. 금액·토큰 상한은 추가 승인 조건이 아니며 사용량 관찰은 유지한다.

## 완료한 준비

별도 [CKE fixture](../tests/fixtures/case_knowledge/README.md)에 6과제의 입력과 평가자 전용 rubric을 분리했다. materials.json에는 고정 커밋의 보고서와 사례 본문 hash, 검토 기록을 남겼다. 기존 MR fixture와 실행기는 수정하지 않았다.

`scripts/evaluate_case_knowledge.py`는 원자료가 같은 source-only/source-plus-case 환경을 준비한다. 사례 본문은 후자에만 제공한다. 24개 독립 작업공간을 준비하고 원자료 보존, 중복 실행·한도 초과 거부, 오류/미완료의 성공 판정 방지, timeout 후 프로세스 그룹 종료를 로컬에서 검사했다. CLI 완료 판정은 기존 실행기의 completed_turn을 재사용한다. 의미 판정은 수동으로 남긴다.

macOS sandbox-exec에서 각 환경의 원자료를 읽을 수 있고 저장소·전역 설정·실제 볼트·다른 조건 파일의 읽기는 거부됨을 24개 환경에서 확인했다. 프로필은 셸 자식 프로세스에도 적용된다. Codex 내부 sandbox는 중첩하지 않고 외부 OS sandbox 안에서 실행하도록 구성했다. 두 환경의 인증 홈을 분리하고 실제 전역 설정·훅·볼트를 변경하지 않았다.

CLI 버전 조회는 Claude 2.1.270, Codex 0.154.0으로 성공했다. 하지만 버전 조회만으로 실제 대화 시작 경로를 검증할 수 없었다는 한계가 아래 첫 실행에서 드러났다.

## 수정과 로컬 재검증

설치된 Claude 바이너리에서 CLAUDE_CODE_TMPDIR 지원을 확인했다. 인증 정보를 제공하지 않고 네트워크를 OS 수준에서 차단한 별도 시작 검증에서, 기존 환경은 같은 EEXIST를 재현했다. CLAUDE_CODE_TMPDIR를 전용 임시 경로로 설정한 환경은 EEXIST 없이 초기화한 뒤 `Not logged in`으로 종료했다. 이것은 실제 인증 모델 호출의 성공이 아니라 임시 경로 문제의 로컬 RED→GREEN이다.

runtime_environment가 TMPDIR와 CLAUDE_CODE_TMPDIR를 모두 실행별 경로로 설정하게 수정했다. 관련 회귀 테스트를 먼저 실패시킨 뒤 GREEN을 확인했다. 새 CKE 테스트 4개를 포함한 전체 로컬 테스트 61개가 통과했고 git diff --check도 통과했다. 금액·토큰 강제 상한은 도입하지 않았다.

수정 구성의 새 24개 작업공간은 `/private/tmp/case-knowledge-20260915-v2`에 준비했지만 모델은 실행하지 않았다. 이 경로의 새 캠페인을 시작하려면 재시도 없는 첫 캠페인과 구분해 실행 승인을 기록하고 실행 직전 자료가 고정돼 있는지 확인해야 한다. 수정 구성의 24개 OS 읽기 격리는 다시 검사해 모두 통과했다. 사례 사람 검토나 금액·토큰 상한을 다시 승인받으려는 것이 아니다.

## 수정 구성 중간 결과와 실행 차단

수정 캠페인은 Claude CKE-001 두 조건을 각각 47.786초·48.227초에 완료했다. 첫 Codex 조건은 0.078초에 CODEX_HOME canonicalize가 Operation not permitted로 실패했다. 총 시작 3건, 정상 완료 2건, 시작 오류 1건, 미실행 21건이다.

Codex는 최종 경로 외에 상위 디렉터리 메타데이터 접근도 필요했다. 네트워크를 차단한 인증 없는 시작 검증에서 `/private/tmp`와 캠페인 루트의 file-read-metadata만 허용하면 경로 오류 없이 시작 이벤트에 도달함을 확인했다. 이후 네트워크 재연결을 기다리는 오프라인 검증 프로세스는 종료했다. 이를 모델 비교 재시도로 세거나 성공으로 보고하지 않는다.

실패한 03번은 재실행하지 않고, 미시작 04~24번의 프로필만 메타데이터 접근 보완 대상으로 준비했다. 프로필 변경 전후 hash와 코드 hash는 별도 phase-2.json에 기록했고 원래 manifest와 처음 3건은 보존했다. 내용 읽기 격리 24환경 검사를 다시 통과했다. 두 완료 조건은 원래 프로필 아래 실행됐으며 이후 조건과의 설정 차이를 숨기지 않는다.

남은 21건 실행은 자동 승인 검토가 거절했다. 사유는 개인 사례 자료의 외부 전송 payload와 Claude/OpenAI 수신처에 대한 구체적 사용자 승인이 없다는 것이다. 기존 “검토 완료”와 수정 구성 진행 승인, Git 추적 자료 목록 및 API base override 부재를 대조해 재검토를 요청했으나 실행은 다시 거절됐다. 이 차단을 우회하지 않았고 04~24번은 not_run이다. 추가로 필요한 승인은 금액·토큰 상한이나 사례 검토가 아니라 명시된 자료의 서비스 전송 승인이다.

완료된 두 restore.sh를 검토 후 별도 임시 복제본의 부재/충돌 조건에서 실행했고 4조건 모두 파일 결과는 통과했다. 다만 source-only는 필수 answer.md가 없고, 두 응답 모두 모델 자체의 검증 복제본을 지시한 workspace 내부 대신 CLI 임시 경로에 만들었다. 실행 완료나 별도 스크립트 동작 통과를 전체 행동 계약 통과로 바꾸지 않는다. 전체 비교 및 사례 효용 결론은 아직 내릴 수 없다.

수정 캠페인 기록은 docs/evaluations/case-knowledge-20260915-v2에 로컬 미추적으로 보존한다. 인증 홈·전체 볼트·전역 설정은 복사하지 않았다. 다음 실행 전 임시 복제본의 실제 경로도 격리·지침 준수 검증에 포함해야 한다. 기존 57개 memory 회귀와 별도로 CKE 로컬 테스트 4개는 통과했다.
