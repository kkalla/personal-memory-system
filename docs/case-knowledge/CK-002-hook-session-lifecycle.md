# CK-002 — 새 세션만 검증한 훅 배포가 진행 중 세션을 막았다

검토 상태: **reviewed**. 2026-09-15 사용자가 사례 CK-001~003의 본문·연결 근거 검토 여부 질문에 “검토 완료”로 답했다. 행동 기억의 confirmed가 아니다.

## 발생 문맥

Claude 운영 연결 중 발생한 사건이며 수정 코드는 208ce19에 포함된다. 관찰일은 보고서 기준 2026-09-14다. 54개는 전체 로컬 테스트 수이며 생명주기 신규 테스트만 54개라는 뜻이 아니다.

## 사례와 근거

- 문맥·검색어: Claude 검색 제어 배포; 훅, 기존 세션, 초기화, 상태 손상, 배포.
- 관찰: UserPromptSubmit 없이 PreToolUse부터 받은 기존 세션에서 denials만 있는 상태가 저장됐고 다음 이벤트가 손상 상태로 거부됐다. 새 세션 스모크는 이 전환 조건을 다루지 않았다(E2).
- 후속 관찰: 기존 경로 비활성화, 불완전 상태 저장 방지, 새 SessionStart 활성화 조건과 별도 상태 경로를 적용했다. 로컬 테스트 54개 및 배포 command를 임시 상태 경로로 실행한 재생에서 기존 세션 무차단·새 세션 검색 전 변경 차단을 확인했다(E2).
- 적용 조건: 요청 상태를 유지하는 제어를 실행 중 클라이언트에 연결하거나 교체할 때. 새 세션, 기존 세션, 다음 요청, compact, resume/clear를 구분해 검증한다.
- 비적용 조건: 수정 후 전체 모델 회귀는 실행하지 않았다. Codex에 같은 Claude 제어가 설치됐다는 뜻도 아니다.
- 추론 후보: 상태를 가진 연동의 배포 검증에는 중간 생명주기 진입이 필요할 수 있다. 모든 오류를 무조건 허용해야 한다는 일반화는 하지 않는다.
- 다음 확인: 설치 전부터 실행 중인 세션을 별도 조건으로 넣고 비활성·초기화·활성 전이를 검증한다.
- E2: [운영 검증 — 기존 Claude 세션 장애와 수정](../memory-operations-validation.md#기존-claude-세션-장애와-수정). 보고서와 코드가 공유 근거이며 원시 재생 자료는 로컬 전용이다.

## 추론의 반증 조건

생명주기 조건을 추가해도 기존 세션 진입 결함을 탐지하지 못하면 검증 조건을 재검토한다. 활성 세션의 정당한 정책 차단까지 해제하는 변경은 이 사례의 적용이 아니다.

## 근거 접근과 버전

위 E 근거의 고정 커밋은 `208ce193ad95487789cb7ec3ae48d83178d8ba9d`다. 이 값은 보고서의 고정 버전이며 당시 실험 구성 커밋과 구분한다. 링크는 현재 문서로 이동하므로 원문이 달라졌다면 고정 커밋의 같은 경로·절을 확인한다.

근거 수준: **추적된 검증 보고서**. 원시 실행 기록은 보고서가 가리키는 로컬 미추적 `docs/evaluations/`에 있어 다른 checkout에서는 열리지 않을 수 있다. 이번 문서 작성은 원시 기록 재판독·실험 재현이 아니다. 근거를 열 수 없거나 상충하는 새 결과가 있으면 needs-review로 전환하고 미확인 주장을 적용 근거로 쓰지 않는다.

## 검토·정정 기록

- 작성·문서 대조: Codex. 고정 커밋의 보고서를 읽고 수치·실패 상태·검증 한계를 대조했다. 사람의 검토나 새 실행 검증을 대신하지 않는다.
- 사람의 근거 대조: 사용자, 2026-09-15 “검토 완료”. 대상은 커밋 8cb33a6의 이 사례 본문과 연결 근거다. 모델 실험 재현을 새로 수행했다는 뜻은 아니다.
- 정정·대체: 없음. 새로운 근거가 생기면 이전 주장과 변경 이유를 보존한다.
