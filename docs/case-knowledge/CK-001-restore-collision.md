# CK-001 — 복원 주의 문구와 실행 명령의 동작이 달랐다

검토 상태: **reviewed**. 2026-09-15 사용자가 사례 CK-001~003의 본문·연결 근거 검토 여부 질문에 “검토 완료”로 답했다. 행동 기억의 confirmed가 아니다.

## 발생 문맥

실패 단계는 e9eb736 기준의 Claude 집중 검증, 후속은 898a4aa 기준의 Claude·Codex 전체 회귀다. 관찰일은 보고서 기준 2026-09-14다.

## 사례와 근거

- 문맥·검색어: personal-memory 복원 안내 검증; 복원, 보관, 충돌, 덮어쓰기.
- 관찰: 일반 mv 명령은 답변에 충돌 주의 문구가 있었어도 별도 충돌 복제본에서 목적지를 덮어썼다. 당시 3명령의 부재 조건은 3/3, 충돌 조건은 2/3 통과했다(E1a).
- 후속 관찰: 실행 코드 자체에 목적지 검사와 mv -n을 포함하도록 지침을 변경한 뒤, 전체 회귀의 실제 명령 12개에 대해 부재 12/12·충돌 12/12를 확인했다(E1b). 시간 절감이나 모든 파일시스템에서의 안전성은 측정하지 않았다.
- 적용 조건: 파일을 보관 위치에서 되돌리는 실행 가능한 안내를 생성·검토하는 작업. 별도 복제본에서 목적지 유무와 양쪽 파일 보존을 확인한다.
- 비적용 조건: 이 기록만으로 동시 쓰기·디렉터리 병합·권한 오류까지 검증됐다고 할 수 없다. mv -n의 종료 코드만으로 실제 이동 완료를 판단하지 않는다.
- 추론 후보: 설명문 검토와 실행 산출물 검증을 분리하면 이런 누락을 찾는 데 도움이 될 수 있다. 다른 작업에서도 재발이 줄어드는지는 비교 검증 필요.
- 다음 확인: 현재 환경에서 부재/충돌 복제본을 만들고 제시할 코드 자체의 파일 결과를 검사한다.
- E1a: [scope/status 검증 — 복원 검증의 별도 실패](../memory-retrieval-t4-scope-status-validation.md#복원-검증의-별도-실패).
- E1b: [복원 검증 — 전체 회귀](../memory-retrieval-t4-restoration-validation.md#전체-회귀). 원시 기록은 해당 문서의 로컬 링크이며 다른 checkout에서는 부재 가능.

## 추론의 반증 조건

동일한 실행 산출물 검증을 추가해도 누락 발견이나 재발 감소가 없으면 이 일반화의 추가 효용은 지지되지 않는다. 필요한 충돌 재검증은 반복 낭비로 세지 않는다.

## 근거 접근과 버전

위 E 근거의 고정 커밋은 `208ce193ad95487789cb7ec3ae48d83178d8ba9d`다. 이 값은 보고서의 고정 버전이며 당시 실험 구성 커밋과 구분한다. 링크는 현재 문서로 이동하므로 원문이 달라졌다면 고정 커밋의 같은 경로·절을 확인한다.

근거 수준: **추적된 검증 보고서**. 원시 실행 기록은 보고서가 가리키는 로컬 미추적 `docs/evaluations/`에 있어 다른 checkout에서는 열리지 않을 수 있다. 이번 문서 작성은 원시 기록 재판독·실험 재현이 아니다. 근거를 열 수 없거나 상충하는 새 결과가 있으면 needs-review로 전환하고 미확인 주장을 적용 근거로 쓰지 않는다.

## 검토·정정 기록

- 작성·문서 대조: Codex. 고정 커밋의 보고서를 읽고 수치·실패 상태·검증 한계를 대조했다. 사람의 검토나 새 실행 검증을 대신하지 않는다.
- 사람의 근거 대조: 사용자, 2026-09-15 “검토 완료”. 대상은 커밋 8cb33a6의 이 사례 본문과 연결 근거다. 모델 실험 재현을 새로 수행했다는 뜻은 아니다.
- 정정·대체: 없음. 새로운 근거가 생기면 이전 주장과 변경 이유를 보존한다.
