# 사례 지식 C4 비교 실행 계획

상태: **승인된 새 캠페인 종료 — 23개 완료·1개 시작 오류**. [최종 결과](../../memory-case-knowledge-c4-results.md)에 11개 비교쌍의 판정과 한계를 기록했다. [C4 기록](../../memory-case-knowledge-c4-validation.md)에 첫 캠페인의 실패 1건·미실행 23건과 수정 검증 이력을 보존한다. 사용자가 2026-09-15 “오케이 수정된 구성으로 진행”으로 새 24세션을 승인해 수정 구성 캠페인을 시작했다. [C3 평가 계약](../../memory-case-knowledge-evaluation-contract.md)을 대상으로 한다. 2026-09-15 사용자가 “C3관련해서 금액·토큰 강제 상한은 우선 배제하고 진행”으로 지시했다. 금액·토큰 강제 상한은 이번 범위에서 제외하고 아래 24세션·600초·재시도 없음으로 진행한다. 이 승인을 사례별 사람의 근거 검토 완료로 해석하지 않는다.

## 범위와 실행량

6과제 × 2조건 × Claude Code/Codex = **최대 24세션·24사용자 턴**, 과제당 한 턴, 자동 재시도 없음. 모델 내부 도구 왕복은 사용자 턴 수와 다르므로 별도 기록한다. 대화 이어하기나 실패한 실행을 교체하는 추가 세션은 없다.

요청 구성은 기존 평가 기준을 이어 Claude `claude-sonnet-5 / high`, Codex `gpt-6-astra / low`로 제안한다. 사용자의 Claude 기본 Sonnet 5 high 선호를 유지하며 Codex 전역 effort를 변경하지 않는다. 실행 준비 때 설치된 CLI가 이 조합을 지원하는지 확인한다. 지원하지 않으면 다른 모델로 자동 대체하지 않는다.

과제 번호가 홀수면 Claude는 source-only 먼저, Codex는 source-plus-case 먼저 실행한다. 짝수면 반대로 한다. 실행은 직렬이며 각 run은 새 임시 작업공간·독립 인증/설정 범위를 사용한다. 승인된 기존 인증 방법만 사용하고 인증을 보고서에 기록하지 않는다.

## 실행량·중단 한도

가격표를 조회하거나 비용을 계산하지 않았으므로 아래는 달러 비용 견적이 아니다. 구독 사용량도 포함하는 **실행량 상한**이다.

| 항목 | 한도 |
| --- | --- |
| 새 모델 세션 | 전체 24회, 시작한 실패 세션도 포함 |
| 사용자 턴 | 세션당 1회 |
| 벽시계 시간 | 세션당 600초, 초과 시 자식 프로세스 종료 및 timeout 기록 |
| 전체 직렬 모델 실행 시간 | 최대 4시간, 준비·사람 검토 시간 제외 |
| 재시도·보충 세션 | 0회 |
| 사용량 기록 | CLI가 보고한 입력·출력·캐시·추론 단위를 원래 의미대로 보존; 미보고는 unknown |
| 금액·토큰의 강제 상한 | 사용자 지시로 이번 평가에서 제외. 추가 확정이나 별도 승인 조건으로 남기지 않음 |

24회와 세션 timeout은 준비 코드에서 실행 전에 검증한다. 금액·토큰 한도 탐색이나 강제 제한 구현은 하지 않는다. 사용량 기록은 유지하되 미보고 항목을 임의 환산하거나 실토큰을 UTF-8 byte로 대체하지 않는다. 금액·토큰 상한 부재를 이유로 다시 승인을 요청하지 않는다.

인증 오류·사용량 제한·원자료 누출·입력 hash 불일치가 발생하면 캠페인을 중단하고 원인을 기록한다. 일반 과제 행동 실패는 보존하고 다음 예정 과제를 진행할 수 있다. timeout이면 다음 세션 시작 전 자식 종료를 확인한다. 원인을 고치더라도 같은 캠페인 안에서 실패 조건만 재실행하지 않는다.

## 준비 순서

1. 사례 3개의 사람 검토자·대상 버전·근거 대조 결과를 기록한다. 설계 승인을 이 검토의 대체로 사용하지 않는다.
2. 실행량·timeout 및 금액/토큰 강제 상한 제외 승인은 위 사용자 지시로 기록했다. 자료 준비는 사람 검토와 병행하되 모델 시작 전 사례 검토 기록을 확인한다.
3. 별도 CKE fixture와 실행 준비 진입점을 만든다. 합성 입력 및 조건별 제공 파일을 고정하고 manifest/hash를 만든다. 기존 MR fixture와 실제 볼트는 수정하지 않는다.
4. 모델 호출 없이 임시 작업공간 준비, 동일 원자료, 사례 제공 차이, 입력 보존, 경로 격리, 프로세스 종료 및 한도 검사를 검증한다. 필요 코드만 TDD로 추가한다.
5. 양쪽 CLI에서 전역 설정·훅·기억·부모 경로의 문서가 격리되는지 확인한다. source-only가 사례를 읽을 수 있거나 조건 간 도구 접근성이 다르면 모델 호출 전에 중단한다. 읽기 전용 선언만으로 OS 격리를 보장한다고 하지 않는다.
6. 고정 순서로 최대 24세션 실행하고 답변·도구 이벤트·파일 결과를 보존한다. CKE-001 스크립트는 검토 후 별도 임시 복제본에서 검사한다.
7. 계약 기준에 따라 수동 판정과 짝 비교를 작성한다. 미실행·오류·실패와 유용성 차이 없음을 그대로 보고한다.

## 산출물과 종료 조건

- 추적 가능 산출물: 별도 과제 fixture, 필요한 최소 준비 코드/테스트, scrub된 집계 보고서, 구성 hash와 판정 기준.
- 로컬 전용: 원시 응답·이벤트·작업공간 및 상세 평가 기록. 기존 `docs/evaluations/` 자료를 커밋하거나 게시하지 않는다.
- 인증값·서명 URL·전체 개인 볼트·전역 설정 사본은 공유 산출물에서 제외한다.
- 비교 결과 후 승인 설계의 C5 진입 기준을 판단한다. 효용 차이가 없으면 그대로 보고하며 사례 추가·의미 검색·자동 저장 구현으로 범위를 넓히지 않는다.

코드·준비 과정에서 기존 실행기에 영향을 준 경우에만 해당 기존 회귀를 수행한다. 모델 44세션 전체 회귀는 이 24세션 계획에 포함하지 않는다. 실제 볼트·CLI 전역 설정·launchd·운영 훅·설치는 변경하지 않는다. 임시 자원만 정리하고 원시 근거는 보존한다. 커밋·푸시는 별도 요청 전 수행하지 않는다.
