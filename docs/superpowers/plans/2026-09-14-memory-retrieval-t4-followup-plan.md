## F1 — 실제 훅 이벤트와 요청별 검색 확인

대상: `scripts/memory_retrieval_hook.py`, `scripts/evaluate_memory_retrieval.py`, 필요한 경우 `scripts/memory_eval_server.py`, 관련 테스트.

### 연결 확인을 먼저 한다

설치된 Claude CLI의 UserPromptSubmit/PreToolUse/PostToolUse/Stop 이벤트를 격리 환경에서 확인한다. 이 이벤트 설계는 구현 제안이며 현재 버전에서 동작 확인된 기능으로 간주하지 않는다. 구현 시작 시 로컬 CLI 도움말과 공식 훅 문서로 payload·차단·재개 의미를 확인한다. 과거 PostToolUse 13회가 모두 빈 출력이었던 원인을 먼저 확인한다. 이전 코드의 응답 경로 가정이나 단순 출력 형식 변경만으로 해결됐다고 판단하지 않는다.

서로 다른 요청 2개를 같은 세션에서 수행하는 소형 프로브와, 검색 오류/정상 0건을 관찰하는 프로브를 준비한다. 합성 임시 기억만 쓴다. 실제 CLI 이벤트에서 요청 시작, 검색 완료 응답, Stop 재진입 여부를 확인한다. 필요한 이벤트가 제공되지 않거나 보정이 작동하지 않으면 F1의 연결 방식부터 재설계하고 전체 회귀를 실행하지 않는다.

### 제안 상태와 동작

- 세션별 임시 디렉터리는 0700, 상태 파일은 0600으로 만든다. 원자적 교체와 잠금을 사용하고 실행기 종료 시 정리한다.
- 상태는 session/request 식별자, 확인된 project_id, 검색 시도 수, `not_searched / returned / empty / error`, 보정 횟수만 보관한다. 기억 본문·인증값은 중복 저장하지 않는다.
- 매 사용자 요청마다 검색 상태를 초기화한다. 이는 자연어 주제 변경을 완벽히 판별하는 대신 모든 새 요청에서 재확인하는 **제안된 보수적 운영 규칙**이다. 동일 요청 내 resolve가 다른 프로젝트/대상을 확인하면 기존 검색 상태를 무효화한다. 식별 도구를 호출하지 않은 암묵적 주제 변경까지 탐지한다고 주장하지 않는다.
- 완료된 memory_search 응답만 상태를 갱신한다. 호출 시도·도구 거부·MCP 오류는 검색 완료가 아니다. 정상 0건은 완료된 검색이지만 관련 기억 반환 성공은 아니다.
- 검색 전에는 Read와 프로젝트 식별·검색을 허용한다. Write/Edit/memory_save/Bash는 내부 사유와 함께 보류하는 방식을 먼저 검증한다. Bash를 정규식으로 안전한 읽기 명령이라 분류하지 않는다. 파일 확인에 Bash가 꼭 필요한 작업에서 교착이 나면 이 제한은 채택하지 않고 한계와 대안을 보고한다.
- 도구 없이 답하려는 경우 Stop 보정은 요청당 최대 1회다. 이미 사용자에게 보인 응답은 평가에서 제거하지 않는다. 보정 후에도 검색이 없으면 연결 fail로 남긴다.
- 같은 원인의 차단을 무한 반복하지 않는다. 보정 한도 소진·상태 손상·검색 오류로 진행할 수 없는 경우 작업 미완료를 기록하고 끝낸다. 실패를 정상 검색 상태로 바꾸지 않는다.
- 제공 기억 모드에는 검색 상태·검색 강제 훅을 적용하지 않는다.

RED → GREEN: 이전 요청의 검색 재사용 거부, 프로젝트 전환 무효화, 정상 0건과 오류 구별, 거부된 도구가 상태를 통과시키지 않음, 동시 요청/지연 응답 격리, 재개, 잘못된 상태 파일, Stop 1회 한도, 종료 정리를 공개 CLI/이벤트 경계에서 검증한다. 같은 세션의 동시 요청을 CLI가 지원하지 않으면 지원하지 않는 것으로 명시하고 요청 오염 방지만 검증한다.

완료 기준: 실제 프로브가 이벤트 연결과 제한/보정 효과를 보여주고, 로컬 상태 전이 검증이 통과한다. 검색 상태의 존재만으로 관련성·행동을 통과시키지 않는다.

## F2 — 미적중 검색어 선택 보강

대상: `scripts/memory-retrieval-instructions.md`, F1에서 검증한 내부 피드백 경계, 관련 테스트.

단일어 형식은 유지하되 첫 검색어를 임의 파일명/예시값보다 **작업 대상의 종류를 나타내는 명사**로 선택하도록 한다. 0건이면 같은 대상의 동의어나 상위 개념으로 최대 두 번 재검색한다. 전체 최대 3회, 같은 project_id/필터를 유지한다. 특정 평가 케이스의 정답 검색어 목록을 지침에 넣지 않는다.

0건 피드백에는 사용한 쿼리와 정상 미적중이라는 사실, 대상 종류에 해당하는 다른 핵심어를 고르라는 절차만 제공한다. 관련 노트 본문/정답/다른 프로젝트 이름을 미리 주입하지 않는다. 실제 훅 응답 관찰이 불가능하면 성공했다고 꾸미지 않고 정적 지침 범위로 축소한 효과를 별도 기록한다.

제품 검색의 AND 의미를 OR·자동 동의어 확장으로 바꾸지 않는다. 같은 문자열 재시도, 후보·다른 프로젝트로 확대, review=true 및 전체 목록 우회는 허용하지 않는다. 단일어 검사와 1–2단어를 권하는 기존 지침의 불일치도 정리한다.

완료 기준: MR-002에서 올바른 프로젝트의 관련 기억이 실제 반환되고, MR-004/005의 무관 기억·후보 제외가 유지된다. 검색만 통과하고 행동이 틀리면 행동 fail이다.

## F3 — 문맥 없는 저장의 범위 결정 보강

대상: `scripts/memory-application-instructions.md`, 필요한 도구 설명과 기존 저장 테스트, 평가 기록.

저장 전 판단 순서를 다음처럼 명시한다.

1. 현재 작업 문맥/등록 프로젝트가 있는지 확인한다.
2. 내용의 확정성과 별도로 적용 범위를 판단한다. “앞으로”, “기억해둬”만으로 전역 범위가 확정됐다고 해석하지 않는다.
3. 프로젝트도 전역 적용의 명시 근거도 없으면 null/candidate로 보관한다. 현재 요청에 어투를 적용하는 것과 장기 기억을 자동 적용 가능한 상태로 저장하는 것을 구별한다.
4. 실제 전역 적용 지시나 사용자 확인이 있으면 기존 계약에 따라 global/confirmed가 가능하다. 모든 프로젝트 문맥 없는 저장을 후보로 강제하는 변경은 하지 않는다.

현재 metadata 검증기는 global/confirmed의 형식적 유효성을 확인할 수 있지만, 모델이 써낸 scope_reason이 실제 사용자 의도와 일치하는지는 보장하지 못한다. scope_reason 필수화나 특정 단어 검사만으로 이 실패를 해결했다고 하지 않는다. 우선 판단 절차·도구 설명을 최소 보강하고 실제 MR-011 제공/회상 두 모드에서 효과를 평가한다.

추가 로컬 검증은 기존 null/confirmed 거부와 null/candidate 허용, 유효한 global/confirmed 보존을 재사용한다. 의미 준수는 모델 검증으로만 판정한다. 최초 저장 시도와 최종 파일 상태를 별도로 기록한다. 실패가 남으면 사용자 확인과 연결된 신뢰 가능한 범위 승인 방식이 필요한지 별도 계약안을 제출한다. 이 계획에서 확인 토큰/API나 모든 전역 저장 차단을 선행 구현하지 않는다.

완료 기준: MR-011 양 모드에서 격리 후보를 실제 저장하고 임의 전역/프로젝트 승격이 없다. 기존 MR-003의 프로젝트 confirmed + scope_inferred 저장도 유지된다.

## F4 — 복원 충돌 검증

대상: 평가 보조 검증과 테스트, `scripts/memory-application-instructions.md`, 검증 문서. 모델의 원시 workspace는 수정하지 않는다.

MR-001/007/009에서 모델이 제시한 실제 복원 명령을 검토한 뒤 별도 복제본 3종에 적용한다.

| 복제본 조건 | 요구 결과 |
| --- | --- |
| 원래 경로의 파일이 없음 | 원래 경로·내용 복원 |
| 원래 경로에 다른 내용의 파일이 있음 | 기존 파일과 archive 원본 모두 보존, 충돌로 복원되지 않았음을 확인 |
| 복원 부모가 없음 | 안내에 부모 생성 절차가 포함되어 실제 복원 가능 |

부모 부재 시험은 archive 파일을 별도로 보존한 합성 구조에서 복원 명령을 검증한다. 현재 archive가 부모 안에 있으므로 부모를 삭제하면서 archive까지 잃어버리는 시험을 만들지 않는다. 모델이 실제로 내놓지 않은 명령으로 대체하거나, 검토 없이 임의 셸 문자열을 실행하지 않는다.

exit 0만으로 복원 성공 처리하지 않는다. mv -n처럼 충돌 때 0을 반환할 수 있는 명령도 내용과 양쪽 경로 상태로 판정한다. 일반 mv가 기존 파일을 덮어쓰는 RED, 안전한 복원 안내와 검증기의 GREEN을 확인한다. 원본 fixture 11개의 역사적 판정과 추가 충돌/부모 부재 판정은 별도 필드로 기록한다.

완료 기준: 최종 보관 사례 12건 각각에서 일반 복원·충돌 보존을 확인하고, 부모 생성 안내의 안전성을 검증한다. 제시된 경로 구조에 부모 부재 조건을 그대로 적용할 수 없으면 합성 검증임을 명시한다.

| 최대 합계 | 각 단계 1회, 실패 반복 재실행 없음 | **56** | **67** |

프로브의 실패·기록 불능이면 집중 회귀로 넘어가지 않는다. 집중 회귀는 10건 전체를 기록한 뒤 판단한다. 기존 5개 실패의 해결, 주제 전환/현재 지시/프로젝트 저장의 회귀 없음, 복원 안전성을 충족해야 전체 44건을 실행한다. 미달이면 남은 예산을 성공할 때까지 재시도하는 데 쓰지 않고 실패와 다음 수정안을 보고한다.

기존 실행기의 요청당 120초 제한, Claude 호출당 max-budget-usd 1을 우선 유지한다. 현재 도구 왕복이 늘어 제한이 부족한 경우 자동 증액하지 않고 실행 장애로 기록한다. 이 값은 Codex를 포함한 전체 지출 상한이 아니며 비용을 보장하지 않는다. 실제 입력/출력/캐시 사용량과 시간을 기록한다.

인증은 이미 허용된 로컬 CLI 인증 경로를 사용한다. Keychain 토큰을 출력·문서·증거에 저장하지 않는다. 기존 임시 저장소·고정 매핑·원시 이벤트·스냅샷·수동 기준별 판정·구성 hash를 재사용한다. 인증/한도/기록기 장애는 첫 장애에서 다음 실행을 중단하며 행동 실패와 분리한다. 증거는 scrub 후 로컬 미추적 자료로 보존하고 코드·테스트·집계 문서만 커밋한다.

## 검증 및 종료 기준

- 변경에 필요한 테스트만 RED → 최소 구현 → GREEN으로 수행한다. 기존 T1/저장/SessionStart/평가 테스트, hooks 테스트, 임시 memory_mcp selftest, fixture 구조 검사, git diff --check를 실행한다.
- 모델 원시 출력과 첫 저장 시도, 최종 상태, 검색 시점/범위/결과, 보정 횟수를 기록한다. Stop 보정 이전 출력도 행동 판정에 포함한다.
- 전체 행동 44/44와 실제 연결 22/22, 별도 복원 안전성 검증 통과가 목표다. 미실행·실행 실패·판정 불충분을 pass로 세지 않는다.
- 통과해도 단일 실행 결과이며 장기 안정성을 보장하지 않는다. 실제 환경 설치는 별도 작업으로 남긴다.
- 최초 제출 시에는 문서만 작성했다. 이후 사용자의 “계획 승인. 진행하자”로 승인받은 범위는 매 요청 재검색 정책, 제한/보정 범위, 56세션·67사용자 턴의 추가 실행량이다.
