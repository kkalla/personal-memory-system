## 실제 프로브 결과

합성 임시 볼트의 2세션·3사용자 턴을 실행했다. 모두 실행 완료했다. 같은 세션의 두 사용자 요청에서 prompt_id가 달라졌고, 최초 Bash는 PreToolUse에서 거부된 뒤 검색 후 수행됐다. 두 번째 요청은 최초 답변 뒤 Stop이 한 번 보정하여 검색을 수행했다. 오류 검색은 PostToolUseFailure, 정상 0건은 PostToolUse로 전달됐다. PostToolUse additionalContext도 실제 출력 이벤트에 포함됐다.

과거 후처리 훅은 tool_response를 content 속성이 있는 객체로 가정했다. 이번 설치 CLI에서는 MCP 응답이 `[ {"type":"text", "text":"[]"} ]` 배열로 왔다. 이것이 과거 정상 0건 피드백이 무반응이었던 구체 원인이다. 새 파서는 관찰한 배열과 객체 content 두 형태를 처리하며 불명확한 결과는 error로 남긴다. [공식 훅 문서](https://code.claude.com/docs/en/hooks)의 이벤트 설명과 설치 CLI 실측을 대조했다. 프로브는 제품 상태 관리 코드 전체의 모델 검증을 대신하지 않는다.

## 구현과 로컬 검증

- 매 사용자 요청의 prompt_id로 검색 상태를 초기화한다. 이전 요청의 지연 응답은 무시하고 세션별 잠금·원자적 파일로 동시 도구 콜을 처리한다. 디렉터리 0700/파일 0600이며 실행기의 임시 홈 종료 때 함께 정리한다. 동일 세션 동시 사용자 요청은 지원을 주장하지 않는다.
- 실제 검색 응답만 returned/empty/error로 분리한다. 정상 0건은 작업 차단을 풀 수 있지만 관련 기억 적중 성공은 아니다. 미적중에는 내부 재검색 안내를 제공한다. 최대 검색 3회, 전체 도구 거부 3회 후 중단, Stop 보정 최대 1회다. 거부 3회는 무한 재시도를 피하기 위해 선택한 구체 구현값이다.
- 성공한 프로젝트 식별 결과의 ID나 대상 경로가 달라지면 검색 상태를 무효화한다. 식별 도구를 사용하지 않은 암묵적 문맥 전환까지 탐지하지 않는다. Read/식별/검색을 허용하며 검색 전 Write/Edit/Bash/기억 저장을 차단한다. provided 모드에는 검색 훅이 없다.
- scope/status 판단 지침을 보강했다. 사용자 저장 요청만으로 전역 적용을 추론하지 않도록 했지만 metadata 형식 검증만으로 사용자 의도 준수를 보장하지 않는다.
- 별도 복제본에서 검토한 실제 복원 argv만 실행하는 보조 검증기를 추가했다. 일반 mv가 exit 0으로 기존 파일을 덮어쓰면 실패한다. mv -n의 충돌 시 exit 0도 복원 성공으로 세지 않는다. 부모 부재는 archive가 복원 부모 밖에 있는 합성 구조에서 검증한다. helper 자체는 임의 명령을 가두는 샌드박스가 아니므로 호출자가 명령을 먼저 검토해야 한다.

현재 구현의 한계: 프로젝트 식별의 실패/진행 중 상태, 필터를 바꾸는 재검색에 대한 강제 정책은 성공 응답의 ID 확인만큼 강하지 않다. 지침의 준수와 최종 trace 판정을 병행하며 이를 완전한 정책 집행기로 설치하지 않는다. 핵심·fixture는 변경하지 않았다.

MR-003은 candidate라는 값 하나만 보고 실패시킨 것이 아니다. 실제 status_reason에 “전역 확정 근거가 없어 후보로 저장”을 이유로 적고, 최종 답변도 “전역 적용 근거가 없어 자동 적용 대상은 아닙니다”라고 설명했다. 현재 프로젝트로 범위를 좁히고 scope_inferred=true를 기록하는 행동은 맞았지만, 전역 범위 확인을 내용 확정의 조건으로 삼아 **기대 행동 3: 명시적 정정 내용과 추정된 적용 범위 구분**을 위반했다. 전역 승격 금지 강화가 이 혼동을 유발했는지는 한 번의 실행만으로 단정하지 않는다.

집중 회귀 trace에는 UserPromptSubmit 11회(회상 9세션의 11턴), PreToolUse 40회, PostToolUse 32회, Stop 11회, 도구 거부 8회가 남았다. 실제 집중 실행에서는 Stop 보정이 필요하지 않았다. Stop 보정의 실동작 근거는 합성 프로브이며 둘을 섞지 않는다. 잘못된 다단어 검색과 예시값 검색은 여전히 있었고 후속 검색에서 기억을 찾았다. 처음부터 올바른 쿼리를 선택했다고 주장하지 않는다.

MR-001/007/009의 실제 복원 명령 3건에 대해 부재·충돌 복제본 총 **6개 검증이 통과**했다. MR-009는 충돌 때 “실패”라고 안내했으나 mv -n의 실제 종료 코드는 0이었다. 내용과 양쪽 파일 보존으로 검증했고, 종료 상태에 대한 설명까지 정확했다고 보지는 않는다. 부모 부재는 합성 로컬 테스트만 검증했다. 최종 12개 보관 사례 전체의 충돌 검증은 전체 회귀 미실행으로 남아 있다.

로컬 테스트 **40개 통과**, 기존 hooks 두 그룹 PASS, 임시 MCP selftest OK, fixture 구조 11개 PASS, git diff --check 통과. 구조/상태 테스트는 모델의 의미 판단 성공을 대신하지 않는다.

총 실제 실행량은 **12세션·15사용자 턴**(프로브 2/3 + 집중 10/12)이다. 승인 계획의 최대 56/67 중 전체 회귀 44/52는 실행하지 않았고, 실패 사례를 추가 실행해 통과로 바꾸지 않았다. Codex 모델 회귀도 이번 단계에서는 실행하지 않았다.

근거는 [프로브](evaluations/memory-retrieval-t4-followup-probes-20260914/) 20개, 집중 캠페인 114개 파일을 로컬에 보존했다. 복사 대상은 scrub 검사 0건이며 원시 증거는 git에 포함하지 않는다. 인증 runner 소스는 env-assign 패턴이 탐지되어 복사 대상에서 제외했다(토큰 값이 아닌 인증 주입 코드). 인증 홈과 토큰은 보존하지 않았다.
