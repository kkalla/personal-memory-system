**새 캠페인 24조건을 각 1회 시도해 23개 완료·1개 CLI 시작 오류로 종료했다.** 완료된 11개 비교쌍은 개선 1쌍·동률 10쌍이다. 사전에 정한 과거 재조사 R1/R3/R5는 양쪽 모두 실행 0회로, 재작업 감소는 관찰하지 못했다. 자동 저장·검색 도입을 정당화하는 결과로 해석하지 않는다.

[평가 계약](memory-case-knowledge-evaluation-contract.md), [실행 계획](superpowers/plans/2026-09-14-memory-case-knowledge-evaluation-plan.md), [준비·실패 기록](memory-case-knowledge-c4-validation.md)을 함께 읽는다. 사용자 승인으로 금액·토큰 강제 상한은 제외했고 세션당 600초·재시도 없음은 유지했다. 사례 본문·연결 근거 검토와 명시적 Claude/OpenAI 자료 전송 승인도 대화에 기록됐다.

## 실제 파일 결과

완료 23건 모두 입력 파일·제공 원자료의 hash가 보존됐다. 설정 변경·원문 삭제·볼트 쓰기는 요청하지 않았고 관찰되지 않았다.

완성된 restore.sh 세 개를 검토한 뒤 독립 복제본에서 실행했다. 목적지 부재 3/3, 충돌 3/3, 합계 **6/6 파일 조건 통과**다. 이 검증은 CKE-001의 하위 조건이며 Claude의 answer.md 누락이나 검증 위치 위반을 상쇄하지 않는다. 부모 부재·동시 쓰기·권한 오류의 보편적 안전성으로 확대하지 않는다.

## 재조사·도구·사용량

R1(옛 일반 mv 실패의 불필요한 재현), R3(이미 설명된 옛 세션 사건의 원시 자료 재확보), R5(동일 판정을 얻기 위한 재실행)는 적용 대상 실행에서 실행·제안 모두 0회였다. 현재 산출물 검증과 미래 수정 구성의 실험 제안은 계약상 R에 포함하지 않는다. 대조 조건 자체가 재조사를 하지 않았으므로 감소 여지가 없었고, 이 결과로 시간이 절감됐다고 주장할 수 없다.

비교 가능한 쌍에서 모델의 네이티브 도구 호출은 Claude 42→45회, Codex 22→20회였다. Claude는 tool_use ID, Codex는 command_execution/file_change 등 도구 완료 ID 단위로 중복을 제거해 셌다. 서로 다른 환경의 수치를 하나의 동일 비용 단위로 합치지 않는다. 셸 오류 복구도 도구 횟수에 포함된다.

Codex CKE-006 plus-case는 run.json만 읽고 case.md와 보고서를 읽지 않았다. 따라서 한 건의 도구 감소를 사례 활용의 효율 개선으로 해석할 수 없다. 이 평가의 source-plus-case는 파일을 추가 제공한 조건이며, 전 조건에서 본문을 모델 문맥에 강제로 주입한 실험은 아니다. 이 차이는 다음 제공 방식 설계에서 다뤄야 한다.

## 환경 변경과 비교 한계

1. 첫 두 Claude 조건은 최초 v2 프로필에서 실행됐다. 세 번째 Codex의 CODEX_HOME 경로 정규화가 실패한 뒤, 미시작 04~24 조건에만 상위 디렉터리 file-read-metadata를 허용했다. 내용 읽기 격리는 다시 검사해 유지됨을 확인했다. 변경 전후 프로필과 코드 hash는 phase-2.json에 보존했다. 이를 하나의 완전히 불변인 실행 환경이라고 보고하지 않는다.
2. 각 비교쌍의 정상 완료 조건은 같은 프로필 단계에 속한다. 그러나 Codex 셸의 here-document 임시 파일 생성 차단 등 환경 오류가 있었고, 모델이 대체 방식으로 파일을 작성했다. 이 추가 작업은 과거 조사 반복과 구분한다. 도구 수·시간 차이는 환경 오류의 영향을 받는다.
3. 사례도 원문도 작고 과제 입력이 명확하다. 이미 충분한 공통 지침이 있고 R의 대조 발생률이 0이어서 실제 재작업 감소를 측정하기에 약한 과제였다.
4. 자동 검색·기억 저장·지속 회상은 실행하지 않았다. 전체 connection은 not_applicable이며, 과제 내부의 과거 검색 기록에 대한 판정과 이번 자동 회상 연결을 혼동하지 않는다.

## C5 후속 판단

**권고: 문서 운영을 유지하고 사례 전용 저장·검색 자동화는 아직 시작하지 않는다.** 승인 설계의 최소 진입 조건 중 사례 검토와 한 유사 과제의 실패 예방은 관찰됐지만, 재작업 감소는 확인되지 않았고 근거 동일성의 과잉 해석도 드러났다. 자동화의 비용과 효용을 판단하기에는 부족하다. 이는 후속 권고이며 새 구현 승인으로 기록하지 않는다.

다음 평가가 필요하다면 실제 사용에서 발생한 반복 조사 과제를 먼저 확보하고, 사례 파일의 제공과 실제 열람을 구분하며, 두 CLI의 셸 임시 경로까지 동일하게 준비해야 한다. 현재 실패를 성공으로 대체하는 재실행이나 사례 수를 늘리는 작업은 이번 범위에 포함하지 않는다.

근거는 로컬 미추적 `docs/evaluations/case-knowledge-20260915-v2/records.json`, 각 실행의 이벤트·답변·파일 hash와 `restore-checks.json`에 보존했다. 원시 자료·인증 홈·실제 볼트는 커밋 대상이 아니다. 기존 제품 코드·운영 설정·memory-tick 훅·MR 회귀 fixture는 이번 평가로 변경하지 않았다.
