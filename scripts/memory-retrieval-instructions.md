# 개인 메모리 검색 절차

사용자가 기억을 요청하지 않아도, 매 새 사용자 요청에서 작업을 파악한 뒤와 같은 요청 안에서 작업 대상·주제가 바뀐 뒤에는 답변 작성·파일 변경·기억 저장보다 먼저 관련 기억을 검색한다. 핵심 본문을 받았다는 사실은 이 검색을 대신하지 않는다. 검색 과정은 내부적으로 수행하고 사용자에게 진행 안내로 출력하지 않는다.

1. 현재 요청에 명시된 등록 project_id가 있으면 memory_project_resolve의 explicit_id로 전달한다. cwd 조회가 null이어도 명시된 ID를 무시하거나 새 ID를 만들지 않는다. 명시 ID가 없으면 작업 대상 경로를 우선하고 cwd를 보조로 사용한다. 식별된 ID를 이후 memory_search의 current_project_id에 전달한다. 문맥이 없거나 충돌하면 프로젝트 기억을 자동 적용하지 않는다.
2. memory_search는 공백으로 나눈 단어가 모두 일치해야 하는 AND 부분문자열 검색이다. 질문 전체를 검색어로 쓰지 않는다. 예시 값이나 개별 파일명보다 작업 대상의 종류·주제를 나타내는 핵심 명사 하나로 시작하며, 조사·동작 요청·출력 형식 같은 부가 단어는 제외한다.
3. 정상 0건이면 같은 대상의 다른 표현이나 상위 개념을 나타내는 핵심 명사 하나로 다시 검색한다. 그래도 0건이면 같은 주제를 뜻하는 다른 핵심어 하나로 한 번 더 검색한다. 같은 문맥에서 최대 3회다. 결과를 찾으면 불필요한 추가 검색을 중단한다. 모든 재검색에서 current_project_id와 적용 범위를 유지한다. 노트 유형을 확신할 수 없으면 kind 필터를 추측해 넣지 않는다.
4. 일반 검색의 재검색을 위해 review=true, 다른 프로젝트 범위, 빈 검색어 또는 전체 인덱스로 확대하지 않는다. 후보 검토를 명시적으로 요청받았거나 아래 저장 전 중복 검토를 수행할 때만 review 조회를 사용한다. API 오류는 정상 0건과 구분하고 확인하지 못한 기억을 찾았다고 하지 않는다.
5. 검색 0건은 사용자가 선호를 갖고 있지 않다는 뜻이 아니다. 현재 요청과 확인된 작업 규칙으로 수행할 수 있으면 진행하고, 필요한 제약을 확인할 수 없으면 미확인 부분만 명시한다. 일치한 기억도 현재 요청·범위·상태를 검토한 뒤 적용한다.

같은 대화의 다음 요청에서 프로젝트나 주제가 바뀌면 이전 검색 결과를 새 작업의 근거로 재사용하지 말고 이 절차를 다시 수행한다.

## 저장 전 중복 검토

일반 검색을 완료하고 저장 가치가 있다고 판단한 때 수행한다. 일반 검색 0건 자체는 이 절차를 시작할 근거가 아니다.

1. `memory_search(query=<주제 명사 하나>, current_project_id=<식별한 ID>, review=true, purpose="save_review")`로 조회한다. 프로젝트를 식별하지 못했으면 ID를 생략한다. `kind`를 추측하지 않으며 `project_filter`는 생략한다. 이는 범위 정보가 없는 legacy/invalid와 global 항목을 놓치지 않기 위한 검토 조회다. 다른 프로젝트 결과도 반환될 수 있다.
2. 결과가 0건이면 같은 주제의 다른 명사로 최대 두 번 더 검색한다. 검토 중 ID·필터는 유지하고 빈 검색어나 전체 인덱스로 확대하지 않는다. 일반 검색과 저장 검토의 횟수는 각각 최대 3회이며, 검토 조회로 일반 검색 한도가 초기화되지는 않는다.
3. 후보의 정확한 `filename`으로 `memory_get(name=filename)`을 호출한다. 다른 slug도 같은 의미일 수 있으므로 본문·범위·상태·근거를 비교한다. 다른 프로젝트는 자동 병합 대상에서 제외한다. legacy/invalid는 프로젝트를 추측하지 말고 원문·현재 사용자 근거로 범위를 확인할 수 있을 때만 다음 단계로 간다.
4. [저장 계약 S9](../docs/memory-retrieval-storage-contract.md#s9--저장-검토와-병합보관-순서)에 따라 새 정보 없음·병합·별도 저장을 결정한다. 검토 조회와 원문 열람만으로 후보 확정·범위 확대·레거시 승격을 하지 않는다.

구버전 MCP가 `purpose`를 지원하지 않거나 훅이 검토를 차단하면 저장 검토 미완료로 알린다. 필터·프로젝트 경로를 바꿔 훅을 우회하거나 볼트 직접 쓰기로 대체하지 않는다. 서버 재시작/지침 재로드 후 다시 수행한다.
